# Задание 3. Создание векторного индекса базы знаний

## 1. Эмбеддинг-модель

- **Название модели:** `BAAI/bge-m3`
- **Репозиторий / API:**
  - Hugging Face: https://huggingface.co/BAAI/bge-m3
  - GitHub (проект FlagEmbedding): https://github.com/FlagOpen/FlagEmbedding
  - Подключается через библиотеку `sentence-transformers`: `SentenceTransformer("BAAI/bge-m3")`
- **Размер эмбеддингов:** 1024 (вектор из 1024 чисел `float32`)

**Дополнительно:**

- Модель многоязычная, поддерживает более 100 языков, включая русский и английский. Поэтому она подходит, если база знаний и вопросы пользователей на разных языках.
- Максимальная длина входного текста: до 8192 токенов, так что длинные фрагменты не обрезаются.
- Размер модели: около 568 млн параметров. На CPU она работает медленнее лёгких моделей вроде `all-MiniLM-L6-v2`, но качество поиска выше.
- Для `IndexFlatIP` эмбеддинги нужно нормализовать (`normalize_embeddings=True`). Тогда скалярное произведение совпадает с косинусной близостью.

## 2. Векторный индекс

- **Библиотека:** FAISS (Facebook AI Similarity Search), разработана Meta. Она быстро ищет похожие векторы среди большого набора.
- **Репозиторий:** https://github.com/facebookresearch/faiss
- **Пакет:** `faiss-cpu` (https://pypi.org/project/faiss-cpu/), версия для процессора, видеокарта не нужна. Установка: `pip install faiss-cpu`.
- **Тип индекса:** `IndexFlatIP`
  - *Flat* означает, что индекс хранит все векторы как есть, без сжатия и приближений. Запрос сравнивается с каждым вектором, поэтому поиск **точный**.
  - *IP* (Inner Product) означает, что близость считается скалярным произведением. Для нормализованных векторов (длина равна 1) оно совпадает с косинусной близостью. Чем больше значение, тем ближе по смыслу.
- **Размерность индекса:** 1024, как у `bge-m3`.

**Почему выбран именно этот индекс:**

- Он не требует обучения: достаточно создать индекс и добавить векторы.
- Результаты точные, потому что ничего не теряется на приближениях.
- Для небольшой базы знаний (до сотен тысяч фрагментов) перебор всех векторов работает достаточно быстро.
- Он простой и надёжный, поэтому его удобно описывать в учебном проекте.

**Ограничения:**

- Скорость поиска растёт линейно с размером базы. Для миллионов фрагментов лучше `IndexHNSWFlat` или `IndexIVFFlat`.
- Индекс хранит только векторы. Тексты фрагментов и метаданные (источник, номер чанка) нужно держать отдельно, например в JSON, а связь идёт по номеру позиции.
- Расход памяти: количество векторов × 1024 × 4 байта. Например, 10 000 фрагментов занимают около 40 МБ.
